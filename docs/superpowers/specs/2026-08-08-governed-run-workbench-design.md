# 受治理运行工作台设计

## 范围与目标

任务 11 提供中文默认的 WebUI，用于浏览任务 8 API 返回的受治理运行。它展示运行和审计事件，不创建、修改或推断后端状态；审批、Planner 配置和上传属于后续任务。

Open Design 证据：2026-08-08 从 `nexu-io/open-design` 官方 Windows x64 Release 安装版本 0.18.1，安装包 SHA-256 已核验。设计采用其“技能/设计系统驱动、真实文件产出、可审计而非装饰性堆叠”的原则；本任务仅使用这些原则，不把 Open Design 运行时纳入产品依赖。

## 信息架构与交互

- 首页使用卡片式运行总览。每张卡片显示运行状态、场景、最近更新时间和最新事件摘要。
- 用户选择一张卡片后，在右侧（窄屏时在卡片下方）显示该运行的完整事件时间线。
- 时间线按 API 顺序显示事件类型、时间、规则结论和工具摘要。阻断与等待审批有中文文本、图标/标签和辅助颜色，不只依赖颜色传达含义。
- 桌面端卡片网格与详情并排；窄屏卡片为单列，详情随选择项显示，避免横向溢出。

## 数据、状态与边界

- `src/api/runs.ts` 是唯一 API 边界，读取任务 8 的运行列表和运行详情。
- 组件接收明确的运行/事件数据；不在 UI 生成假事件、假审批状态或工具结果。
- 有独立的加载、空列表、API 失败和选中运行状态；失败信息不回显内部路径或凭据。
- 本任务不包含写 API 请求、Planner key、上传内容、策略编辑或审批决策。

## 可访问性与验证

- 卡片是可键盘聚焦和选择的控件，包含中文可访问名称；时间线状态有可读文本。
- 测试覆盖阻断事件、空状态、加载、API 错误、卡片选择与窄屏布局的关键 class/结构。
- 使用 Vitest 运行前端测试，并以 Vite build 验证可构建性。

## 自查

- 没有 TBD/TODO 或待定视觉/数据边界。
- 卡片总览与详情时间线不冲突：前者用于选择，后者用于审计。
- 范围仅覆盖任务 11，未提前实现任务 12 的写操作或敏感录入。
