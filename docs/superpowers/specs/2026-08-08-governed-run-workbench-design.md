# 受治理运行工作台设计

## 范围与目标

任务 11 提供中文默认的 WebUI，用于浏览任务 8 API 返回的受治理运行安全摘要和安全事件时间线。它不创建、修改或推断后端状态；审批、Planner 配置和上传属于后续任务。

Open Design 证据边界：2026-08-08 的过程记录称当时从 `nexu-io/open-design` Windows x64 Release 安装了 0.18.1，并称当时做过 SHA-256 校验；本地没有保留安装包、资产 URL 或精确摘要，因此该历史声明当前不可复现，也不作为可验证的校验成功证据。绝不猜测或补写摘要值。设计采用记录中的“技能/设计系统驱动、真实文件产出、可审计而非装饰性堆叠”原则；本任务仅使用这些原则，不把 Open Design 运行时纳入产品依赖。

## 信息架构与交互

- 首页使用卡片式运行总览。卡片只消费列表 DTO 的四个字段 `id`、`scenario`、`status`、`updated_at`；界面显示场景、状态和 UTC 最近更新时间，`id` 只用于选择身份。
- 用户选择一张卡片后，在右侧详情区显示该运行的安全事件 DTO 时间线。
- 时间线只消费五个字段 `type`、`created_at`、`level`、`display_status`、`summary_code`，按 API 顺序显示事件类型、UTC 时间、固定展示状态和固定摘要码，并以 `level` 提供辅助颜色。界面不接收或展示原始事件、工具输出、规则原因或任意摘要文本。
- 桌面端卡片网格与详情并排；CSS 在 `44rem` 以下切为单列并设置溢出保护。这只是实现意图，320px 浏览器验证仍属于未完成的任务 13，不在任务 11 声称已测试。

## 数据、状态与边界

- `src/api/runs.ts` 是唯一 API 边界，列表严格投影四字段安全 DTO，详情事件严格投影五字段安全 DTO。
- 组件接收明确的运行/事件数据；不在 UI 生成假事件、假审批状态或工具结果。
- 原始事件文本即使出现在响应中也不会进入组件数据；未知或缺失安全字段会以固定中文错误失败关闭。
- 有独立的加载、空列表、API 失败和选中运行状态；失败信息不回显内部路径或凭据。
- 本任务不包含写 API 请求、Planner key、上传内容、策略编辑或审批决策。

## 可访问性与验证

- 卡片是可键盘聚焦和选择的控件，包含中文可访问名称；时间线状态有可读文本。
- 单元测试覆盖阻断事件、空状态、加载、API 错误、卡片选择、乱序详情响应、UTC 标注和卡片可访问名称。任务 11 没有窄屏浏览器测试。
- 使用 Vitest 运行前端测试，并以 Vite build 验证可构建性。

## 自查

- 没有 TBD/TODO 或待定视觉/数据边界。
- 卡片总览与详情时间线不冲突：前者用于选择，后者用于审计。
- 范围仅覆盖任务 11，未提前实现任务 12 的写操作或敏感录入。
